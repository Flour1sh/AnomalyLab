## 一、v0.2 实现了什么

### 1. 核心游玩循环

玩家每轮面对三个并排的候选箱。箱型从安全、危险、未知中生成，保证至少两种类型；未知箱在生成时确定一个隐藏配置。玩家可以观察外观线索、用仪器扫描，也可以直接开箱。每轮只能选一个箱子，其他箱子随即锁定。箱子的配置决定高价值、垃圾和威胁的抽取权重；高价值金额从对应区间抽取，奖励由 Wallet 统一入账。

结果展示后进入回合决策。玩家可继续下一轮或撤离；成功解决第二次威胁后只能撤离。撤离、死亡和技术异常使用不同终局，记录金额、完成回合、成功收容次数和本局用时；重新开始通过关卡重载清理局内状态。

### 3. 主要实现方式

- C++ 承担箱子定义与结果、Wallet、Scanner、Health、威胁生命周期、回合状态和统计的权威逻辑；Blueprint 保留交互入口、输入适配、外观与 UI 展示。
- Python 构建脚本生成或更新组件与 Widget 的 `.uasset`，并在新编辑器进程重载核对。装备及外观模型由可重建的 Blender 脚本生成。
- 开发测试使用命令行真实关卡和独立 EXE 的隐藏 `NullRHI` 进程。正常游戏不会自动生成测试驱动；它们只在带测试参数的 Development 启动中运行。

## 二、没有实现什么

以下是 v0.2 原型范围外、目前没有做成可玩功能的项目：

- **枪械战斗：**枪是装备占位模型，鼠标点击不射击；没有弹药、命中、怪物受伤或击杀奖励。怪物血量等字段仅为后续扩展保留。
- **商店与成长：**没有购买、解锁、扫描仪升级、玩家属性升级或逐轮难度递增。
- **完整背包与持久化：**没有拖拽背包、拾取/丢弃系统、跨局存档或长期进度。
- **联网和正式发行配置：**没有多人或联网流程；交付目标是 Win64 Development，未交付 Shipping 版本。
- **强制局时长规则：**3–5 分钟是设计调参目标，不是已实现的倒计时上限或胜负条件。

## 三、已实现但尚未完成的验证

这部分不能写成“功能没有实现”，也不能写成“已经验收通过”：

1. **可见体验：**自动运行使用 `NullRHI`，未核对实际画面、中文字形、动画遮挡、材质、声音或 1280×720/1920×1080 的最终像素效果。两档分辨率的 28 项结果只验证面板矩形位置。
2. **真实操作：**自动驱动直接调用玩法接口，没有注入或人工逐项验证实体 `E/Q/1/2/R` 键、鼠标观察和连续操作时序；T11–T14 的用户验收记录仍按原记录有效。
3. **可见 PIE 与试玩平衡：**没有进行可见 PIE 全流程、3–5 分钟的真实局长统计或随机/低风险/高收益策略试玩。20 秒追逐是否在各种地形与玩家路线下始终具有预期体验，仍需要试玩判断。
4. **剩余异常专项：**自动测试覆盖了威胁生成失败、重复交互、过早结算和死亡互斥；候选箱部分生成失败、奖励外观失败、持续寻路失败及倒计时临界竞争尚无完整专项报告。不能由正常倒计时通过推断所有寻路故障已处理。
5. **T15–T18 人工验收：**这些阶段只有自动测试记录，没有用户提交的逐项可见画面验收结论。
